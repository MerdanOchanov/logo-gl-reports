# Конструктор бухгалтерских отчётов поверх Logo Tiger

Веб-приложение для бухгалтерии: строит отчёты по главной книге **Logo Tiger** (база MSSQL) и показывает их в браузере. Данные из Logo берутся
**только чтением** — ни записи, ни изменения схемы; собственные настройки лежат в отдельных файлах SQLite. Интерфейс на русском языке.

## Что умеет

- Оборотно-сальдовая ведомость (свёрнутое и развёрнутое сальдо), карточка и анализ счёта, главная книга, шахматка, журнал-ордер (в том числе с графами по бланку).
- Формы по строкам (баланс, отчёт о прибылях и убытках и т. п.) с формулами над счетами, выгрузка формы в ваш Excel-бланк.
- Сравнение лет, разрывы переноса остатков между годами, связи счетов между годами.
- Классификаторы счетов (своя группировка, в том числе российские коды), расшифровка любой ячейки до проводок и ордера.
- Отбор по подразделению, отделу, источнику и автору ордера; экспорт в Excel и печать.
- Несколько наборов данных (баз Logo или разных разметок одной базы), роли пользователей (просмотр, редактор, администратор), перенос настроек между наборами.

## Требования

- Windows 10/11 или Windows Server, PowerShell 5.1+ (или `pwsh`).
- Python 3.11+ в `PATH` (код `backend/app` совместим и с Python 3.8: запуск без PowerShell — `python -m app` из папки `backend`).
- Драйвер ODBC для SQL Server (подбирается сам: ODBC Driver 17, 13, SQL Server Native Client 11.0 / 10.0, встроенный «SQL Server», в последнюю очередь ODBC Driver 18)
  и сетевой доступ к серверу MSSQL с базой Logo.
- Node.js 20+ с npm — только для сборки интерфейса (если нет папки `frontend\dist`). Там, где интерфейс уже собран, Node не нужен.

## Запуск

```powershell
.\run.ps1                # создаёт .venv, ставит зависимости, при отсутствии frontend\dist собирает интерфейс, запускает сервер
```

Сервер открывается на http://localhost:8790 (порт — переменная `PORT` или `[app] port` в `config.ini`). Режимы: `.\run.ps1 -CheckOnly` — проверить окружение
и связь с Logo, сервер не запускать; `.\run.ps1 -Build` — пересобрать интерфейс. После правок бэкенда сервер перезапускается.

## Подключение к Logo

Подключение (сервер, база, логин, пароль) задаётся одним из способов:

1. **В интерфейсе:** Настройки → Подключение. Пароль хранится зашифрованным средствами Windows (DPAPI) в `data\registry.db`.
2. **Файлом `config.ini`:** скопируйте `config.ini.example` в `config.ini` рядом с программой (или в `data\`; другое место — переменная `CONFIG_FILE`) и впишите значения.
3. **Переменными окружения** `LOGO_SERVER`, `LOGO_USER`, `LOGO_PASSWORD`, `LOGO_DB`, `LOGO_DRIVER` — они главнее значений из файла.

```ini
[logo]
server = my-sql-server
user = logo_reader
password = ********
database = LOGO_DB

[app]
port = 8790
auth = 0
```

После подключения: **Настройки → Книги и годы** → «Прочитать фирмы из Logo» → принять предложение программы → «Сохранить разметку»; затем «Синхронизировать».
Книга — это источник Logo (фирма и период) с диапазоном дат, меткой года, делителем деноминации и признаком OEM-текстов; мастер подбирает разметку сам.

## Logo только читается

Приложение ничего не пишет в Logo и само отказывается выполнять что-либо, кроме `SELECT`. Надёжная защита — права логина: шаблон скрипта для SQL Server,
который создаёт логин с правом только чтения и явным запретом записи, лежит в `docs\logo-readonly-login.sql` (приложением не запускается; пароль в файле замените на свой).
О хранении паролей и о том, как сообщить об уязвимости, — в [SECURITY.md](SECURITY.md).

## Данные и резервные копии

Всё в папке `data\` (не в исходниках, в репозиторий не попадает):

- `settings.db` — настройки основного набора: классификаторы, сохранённые отчёты, правила, связи счетов; **резервировать обязательно**;
- `registry.db` — подключения, список наборов данных, пользователи и права; **тоже резервировать**;
- `cache.db` — кэш проводок из Logo; одноразовый, при удалении загрузится заново, в резервную копию не входит;
- `templates\` — загруженные Excel-бланки; `ds\<номер>\` — файлы остальных наборов данных.

```powershell
.\backup.ps1              # консистентная копия настроек в backups\settings-ГГГГ-ММ-ДД_ЧЧММСС\
.\backup.ps1 -Keep 30     # и оставить только 30 последних копий
```

## Вход по паролю

По умолчанию (`AUTH=0`) все запросы выполняются от имени администратора — только для доверенной локальной сети. Для входа по паролю:

```powershell
$env:AUTH = '1'; $env:ADMIN_LOGIN = 'admin'; $env:ADMIN_PASSWORD = '<надёжный пароль>'
.\run.ps1
```

Остальных пользователей и их роли на наборах данных администратор заводит в **Настройки → Пользователи**.

## Основные переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LOGO_SERVER`, `LOGO_USER`, `LOGO_PASSWORD`, `LOGO_DB`, `LOGO_DRIVER` | — / `LOGO_DB` / автоподбор | подключение к Logo (логин лучше только для чтения) |
| `DATA_DIR` | `<проект>\data` | где лежат `settings.db`, `cache.db`, `templates\` |
| `PORT` | `8790` | порт сервера |
| `AUTH` | `0` | `1` — включить вход по паролю |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | — | первый администратор при первом запуске с `AUTH=1` |
| `SECRET_KEY` | файл `data\.secret` | ключ подписи сессий (по умолчанию создаётся сам) |
