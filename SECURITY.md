# Безопасность

## Что делает приложение
- Приложение **только читает** Logo: допускаются лишь запросы SELECT/WITH (проверка в `backend/app/logo.py`). Для надёжности используйте логин SQL Server
  с правами только на чтение (шаблон — `docs/logo-readonly-login.sql`).
- Собственные настройки и кэш лежат в папке `data\` (SQLite). Она не должна попадать в репозиторий.

## Где хранятся пароли
- Пароль подключения к Logo хранится в `data\registry.db` в зашифрованном виде (Windows DPAPI, привязка к учётной записи или машине).
  Если шифрование Windows недоступно, интерфейс показывает предупреждение.
- Пароли пользователей приложения (при `AUTH=1`) хранятся в виде хэшей; ключ подписи сессий — в `data\.secret` или переменной `SECRET_KEY`.
- Допустимо задать подключение через `config.ini` или переменные `LOGO_*`: файл `config.ini` содержит пароль открытым текстом, поэтому ограничьте к нему доступ.

## Что нельзя коммитить
`config.ini`, каталог `data\` (`*.db`, `.secret`, шаблоны с данными), резервные копии (`backups\`), логи, выгрузки Excel/CSV/JSON с реальными данными,
архивы сборки. Всё это перечислено в `.gitignore`; перед публикацией проверяйте `git status`.

## Как сообщить об уязвимости
Пожалуйста, не создавайте публичный issue. Используйте закрытое сообщение GitHub: вкладка **Security → Report a vulnerability**
(GitHub Security Advisories) в этом репозитории. Приложите шаги воспроизведения, не включая реальные пароли и данные.

Если секрет случайно попал в историю репозитория, смените его (пароль логина Logo) и пересоздайте историю, а не просто удаляйте файл новым коммитом.
